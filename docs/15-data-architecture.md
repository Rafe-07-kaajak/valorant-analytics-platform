# Data Ownership

Every stage of the data pipeline owns a specific representation of the data.

Each stage is responsible only for its own output and should never modify data owned by another stage.

This separation ensures consistency, reproducibility, and easier debugging.

---

## Ownership Flow

```
External Source

↓

Raw Data

↓

Validated Data

↓

Normalized Data

↓

Feature Data

↓

Prediction Data

↓

Frontend View
```

Each layer has a single owner.

---

## Raw Data

Raw data is the closest representation of the original source.

Responsibilities:

- preserve original values
- preserve timestamps
- preserve source identifiers

Raw data should never be modified manually.

If corrections are required, they should occur in later stages.

---

## Validated Data

Validated data confirms that the required information exists and follows expected formats.

Validation may:

- reject incomplete records
- reject unsupported formats
- reject inconsistent values

Validation should never invent missing information.

---

## Normalized Data

Normalization creates one consistent internal representation.

Responsibilities include:

- standardized identifiers
- unified naming
- consistent date formats
- normalized statistics

Normalization should not change the meaning of the original data.

---

## Feature Data

Feature data transforms normalized information into domain concepts.

Examples include:

- Momentum
- Economy Discipline
- Opening Strength
- Consistency

Features represent analytical knowledge rather than raw statistics.

---

## Prediction Data

Prediction data contains outputs generated by the prediction pipeline.

Examples include:

- predicted winner
- win probability
- confidence
- Match DNA
- explanation

Prediction data should always reference the feature set that produced it.

---

## Frontend View

The frontend consumes prediction-ready information.

It should never:

- modify prediction results
- calculate analytical metrics
- reconstruct business logic

The frontend is responsible only for presentation.

---

## Ownership Rules

Each layer may read data from previous stages.

Each layer should only write data within its own responsibility.

Changes should always flow forward.

Backward modifications should be avoided.

---

## Benefits

Clear ownership provides:

- easier debugging
- reproducible predictions
- simpler testing
- improved maintainability
- predictable data flow

Every piece of data should have one clear owner throughout its lifecycle.
