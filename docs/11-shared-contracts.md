# Shared Contracts

Version: 1.0

Status: LOCKED

---

# Purpose

Shared Contracts define the common language shared by every part of the platform.

Every application, package, service, and future AI component must communicate using these contracts.

No module should invent its own data structures.

---

# Design Principles

A contract should represent a business concept rather than an implementation detail.

Contracts should remain stable even if the underlying technology changes.

Business language always has priority over database schema.

---

# Core Entities

Version 1 contains the following core entities.

---

## Team

Represents a professional Valorant team.

Properties include:

- identifier
- display name
- region
- logo
- current roster
- Team DNA
- recent performance

A Team is the central entity of the platform.

---

## Player

Represents an individual professional player.

Properties include:

- identifier
- nickname
- role
- preferred agents
- statistics
- recent matches

Players always belong to exactly one team within a prediction.

---

## Match

Represents one competitive match.

Contains:

- Team A
- Team B
- tournament
- format
- map pool
- prediction
- result (if available)

A Match is the primary interaction object inside Prediction Studio.

---

## Map

Represents one playable map.

Examples include:

- Ascent
- Haven
- Bind
- Lotus
- Pearl
- Split
- Sunset
- Icebox

Maps are treated as independent strategic environments.

---

## Team DNA

Represents the behavioral identity of a team.

Contains multiple dimensions describing playstyle.

Examples:

- aggression
- adaptability
- utility efficiency
- economy discipline
- clutch ability
- map control
- tempo

Team DNA is generated by the Prediction Engine.

---

## Match DNA

Represents the interaction between two Team DNA profiles.

Contains:

- similarity score
- conflicting traits
- complementary traits
- decisive characteristics

Match DNA exists only during comparison.

It is never stored as historical identity.

---

## Prediction

Represents the output of the Prediction Engine.

Contains:

- win probability
- confidence
- explanation
- influencing factors
- generated timestamp

Predictions are immutable once generated.

---

## Insight

Represents a human-readable explanation.

Examples include:

- strongest advantage
- biggest weakness
- deciding factor
- confidence explanation

Insights exist to improve understanding rather than accuracy.

# Ownership

Each contract has a single owner.

For example:

Prediction Engine owns Prediction.

Prediction Studio consumes Prediction.

Prediction Studio must never modify Prediction.

---

# Versioning

Contracts should evolve through versioning rather than replacement.

Breaking changes should introduce a new contract version.

Existing consumers should remain functional whenever possible.

---

# Serialization

Contracts should remain platform independent.

They should be serializable between:

- frontend
- backend
- AI modules
- future APIs

No contract should depend on a specific framework.
