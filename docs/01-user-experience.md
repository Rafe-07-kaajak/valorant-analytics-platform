# Purpose

This document defines the intended experience of using the platform.

Rather than describing what users click, this document describes:

- what users are trying to achieve,
- what they are thinking,
- what they should learn,
- how every screen contributes to that learning.

Every interface decision should align with this experience.

---

# Core Experience

Users should never feel like they are using a prediction calculator.

They should feel like they are exploring professional Valorant through data.

Prediction is only the starting point.

Understanding is the destination.

---

# Experience Principles

## Curiosity Before Interaction

The interface should immediately encourage exploration.

Users should naturally ask:

"What happens if I change this?"

---

## Learning Through Experimentation

The platform teaches by allowing users to modify assumptions.

Learning comes from interaction rather than reading documentation.

---

## Transparency Creates Trust

Every important number should have an explanation.

The interface should never ask users to blindly trust the system.

---

## Exploration Should Feel Fast

Changing assumptions should feel immediate.

Slow feedback interrupts learning.

---

## Simplicity Over Density

Although the platform contains complex analytics, the interface should always feel approachable.

Complexity belongs behind the scenes.

---

# Emotional Journey

## Stage 1

Curiosity

The user arrives wondering:

"Who is likely to win?"

---

## Stage 2

Exploration

The user selects two teams and configures the scenario.

They begin asking:

"What if..."

---

## Stage 3

Discovery

The prediction appears together with explanations.

The user discovers that the result is driven by multiple factors rather than a single statistic.

---

## Stage 4

Experimentation

The user changes maps, series format, or feature weights.

They observe how predictions evolve.

---

## Stage 5

Understanding

The user understands which competitive factors matter most.

The prediction becomes meaningful.

---

## Stage 6

Confidence

Trust comes from transparency rather than authority.

Users understand why the platform reached its conclusion.

---

# User Questions

Every screen answers exactly one primary question.

Landing

Who will win?

Prediction Studio

Explanation

Scenario Mode

# Prediction Studio Responsibilities

## User Goal

Understand the competitive matchup.

---

## System Responsibility

Generate trustworthy predictions with clear explanations.

---

## Success Signals

The user:

- modifies at least one assumption,
- understands why the prediction changes,
- gains at least one new insight before leaving.

# Product Personality

The platform should feel:

- professional,
- analytical,
- modern,
- trustworthy,
- interactive.

It should never feel like:

- a betting website,
- a spreadsheet,
- a statistics dashboard,
- a machine learning demo.

---

# Design Philosophy

Every interaction should satisfy at least one of three goals:

Teach something.

Reveal something.

Allow experimentation.

If an interaction satisfies none of these goals, it should not exist.

---

# Final Principle

The product succeeds when users leave with greater understanding than they had before arriving.

Predictions are temporary.

Understanding is permanent.
